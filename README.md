# Сервис для бронирования комнат.

## Cтек

* **Язык разработки:** Python 3.13
* **Фреймворк:** FastAPI
* **База данных:** PostgreSQL 18.4, SQLAlchemy 2.0, Alembic
* **Управление зависимостями:** Poetry 2.4.1
* **Контейнеризация:** Docker / Docker Compose

---

**Значения по умолчанию предназначены исключительно для демонстрации.**

| Переменная                        | Значение по умолчанию                                              | Описание                                      |
|:----------------------------------|:-------------------------------------------------------------------|:----------------------------------------------|
| **`SECRET_KEY`**                  | `cebe80051e45db6a2c7c95e57209b4be000571150b888fe572e30a268b408681` | Секретный ключ для подписи JWT-токенов.       |

| **`POSTGRES_PORT`**               | `5432`                                                             | Порт базы данных                              |
| **`TIMEZONE_DEFAULT`**            | `Asia/Yekaterinburg`                                               | Часовой пояс системы                          |

## Авторизация и аутентификация

Сервис реализует схему аутентификации **OAuth2**.

`POST /auth/login` принимает данные с заголовком
`Content-Type: application/x-www-form-urlencoded`.

Для всех других запросов необходимо добавлять заголовок `Authorization: Bearer <token>`,
где `<token>` заменяется на поле `access_token` из результата выполнения
`POST /auth/login`.

## Сценарий тестирования в Swagger UI

### Шаг 1: Авторизация

1. Перейдите по адресу: `http://localhost:8000` или `http://localhost:8000/docs`.
2. Нажмите кнопку **Authorize** в правом верхнем углу. Эта форма выполнит запрос на
   `POST /auth/login` для автоматического проставления токена доступа в заголовок
   `Authorization` на другие запросы.
3. Введите учетные данные в поля формы и нажмите кнопку **Login**.

Для демонстрации возможностей в системе заранее созданы тестовые пользователи:

| Логин          | Пароль     | Права доступа                                                                                           |
|:---------------|:-----------|:--------------------------------------------------------------------------------------------------------|
| **`admin`**    | `admin`    | **Администратор** — полный доступ                                                                       |
| **`employee`** | `employee` | **Сотрудник** — просмотр доступности всех бронирований, бронирование слотов и отмена своих бронирований |

### Шаг 2: Просмотр статусов бронирований комнат и слотов

* С помощью `GET /bookings` мы можем получить данные всех комнат, их временных слотов и
  статусов бронирований.

1. **Заголовок `x-timezone`**: Если не указан, будет использован параметр
   `TIMEZONE_DEFAULT`. Принимает формат IANA (`Asia/Novosibirsk`).
2. **Параметр `target_date`**: Если не указан, будет использована текущая дата для
   указанного часового пояса. Принимает формат ISO 8601 `YYYY-MM-DD`.

* **Ожидаемый результат (`200 OK`)**: Получаем данных всех комнат, их временных слотов и
  статусов бронирований.

### Шаг 3: Бронирование временного слота

* С помощью `POST /bookings` мы можем забронировать временной слот с комнатой на дату.

1. **Заголовок `x-timezone`**: Если не указан, будет использован параметр
   `TIMEZONE_DEFAULT`. Принимает формат IANA (`Asia/Novosibirsk`).
2. **Тело**: Необходимо передать ID комнаты, ID временного слота, полученные из `Шага 2`
   и целевую дату.

* **Ожидаемый результат (`201 Created`)**: Бронирование создано.
* **Проверка результата**: При повторном выполнении `Шага 2` можно убедиться, что статус
  изменился на `BOOKED`, а повторная попытка создания вернет ошибку `409 Conflict`.

### Шаг 4: Отмена бронирования

* С помощью `DELETE /bookings/{booking_id}` мы можем отменить бронирование

1. **Путь `booking_id`**: Необходимо вставить полученный `id` из `Шага 3` или
   `booking_id`
   со статусом `BOOKED` из `Шага 2`.

* **Ожидаемый результат (`204 No Content`)**: Бронирование отменено.
* **Проверка результата**: Если вы повторно выполните запрос из `Шага 2` на ту же дату,
  статус этого слота вернется на `FREE`, а повторная попытка отмены вернет ошибку
  `404 Not Found`.

### Проверка ролевой модели:

1. Выполните авторизацию с правами доступа `Администратор` из `Шага 1`
2. Забронируйте слот с помощью `Шагов 2 и 3` и запомните идентификатор бронирования.
3. Выполните авторизацию под другим пользователем с правами доступа `Сотрудник` из
   `Шага 1`
4. Попробуйте удалить бронирование с ранее сохраненными идентификатором с помощью
   `Шага 4`

* **Ожидаемый результат (`403 Forbidden`)**: Так как отмена сотрудником чужого
  бронирования запрещена политикой системы. Отменять любые бронирования без ограничений
  может только администратор.

## Способы запуска приложения

### 1. Docker Compose

Убедитесь, что у вас установлен Docker и выполните команду:

```bash
docker compose up --build
```

### Порядок запуска сервисов:

1. **`db`** - База данных PostgreSQL.
2. **`migrate`** - Одноразовый контейнер для миграций.
3. **`api`** - Основной контейнер.

### 2. Локально

1. **Запустите базу данных PostgreSQL**.
   <details>
   <summary>Запуск PostgreSQL в Docker</summary>

   ```bash
   docker run --name meeting-db -d -p 5432:5432 -e POSTGRES_DB=meeting -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres postgres:18.4-alpine
   ```
   </details>

2. Установите зависимости проекта:
   ```bash
   poetry install --no-root
   ```

3. Примените миграции:

   ```bash
   alembic upgrade head
   ```

4. Запустите сервер:

   ```bash
   uvicorn app.main:app --log-config log_config.json
   ```

## Запуск тестов

Для интеграционных тестов используется библиотека `testcontainers`, поэтому **Docker
должен быть запущен**, иначе тесты завершатся ошибкой.

### Запуск тестов

1. Установите зависимости проекта:
   ```bash
   poetry install --no-root
   ```
2. Запустите тесты:
   ```bash
   poetry run pytest
   ```
